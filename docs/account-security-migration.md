# 账号找回与会话撤销（2.1.6+56）

## 认证边界与行为

- `/auth/login` 保留新号码直接注册的旧客户端契约；已有密码账号必须验证密码。无密码旧账号与密码错误统一返回 401 和迁移提示，不写密码、不签发 token。
- 手机号仅为登录标识，项目未验证号码归属，也没有已验证邮箱、短信、Passkey 或 OAuth。新注册不证明号码归属；不能以新接管邮箱、手机号、家庭资料、邀请链接或旧会话作为找回凭据。
- `POST /auth/recovery-code` 要求有效 Bearer 与当前密码，签发 256 bit 随机恢复码，返回 `recovery_code` 与 `expires_at`。只展示一次，响应 `Cache-Control: no-store`；数据库只存 SHA-256 摘要与一年有效期。再次生成替换旧码。恢复码是持有凭据，应离线保存，不进入日志、URL、事件分析或持久化客户端缓存。
- `POST /auth/reset-password` 提交 `phone`、`recovery_code`、`new_password`。不存在账号、错误、过期、已消费恢复码返回相同 401；成功只报告状态，不直接签发登录 token。消费恢复码、改密码与删除该账号全部 session 在一个事务提交。
- `POST /auth/change-password` 必须提供有效 Bearer 与正确旧密码。成功撤销包括当前设备在内的全部 session，并作废恢复码，需重新登录后生成新码。
- `/auth/logout` 幂等撤销提交的当前 Bearer；新增 `/auth/logout-all` 只操作当前 Bearer 所属账号，不接收目标账号参数。成功后包括当前 token 在内全部失效。
- token 每次从数据库解析，没有 token 校验缓存。过期、已撤销、无密码旧账号的历史 token 一律拒绝。撤销提交后开始认证的请求立即失败；此前已经通过鉴权的在途请求可能完成，无法追回已经返回的数据。
- 登录校验与签发、恢复码生成、重置、改密、当前与全部撤销持有同一个用户行锁。等待行锁的敏感操作重新验证 Bearer，防止用撤销前读到的身份继续生成恢复码。恢复码原子消费，两个并发重置最多一个成功。
- 注册相同号码的并发冲突不会覆盖既有账号，失败返回通用认证错误。新注册+登录的兼容接口仍可通过成功注册与登录失败推断号码是否占用；不能声称隐藏了注册占用情况。找回接口没有账号查询/预检端点，响应不泄露存在性。彻底隐藏注册占用或验证号码归属需另行确定产品流程与可信验证渠道。
- 复用现有限流器限制登录、恢复、恢复码生成和改密；按 IP 与标准化号码/已认证用户限流。现有限流是单进程内存实现，重启后重置，多 worker/多实例会放大额度；上线扩容前需共享限流存储。高熵恢复码不适用短数字验证码。

## 旧账号迁移

1. 无密码且无可信恢复因子的账号安全锁定：不能登录、不能使用历史 Bearer、不能靠旧客户端自动设密。schema migration 只增加可空字段，不回填恢复码、不重置任何用户密码、不修改真实 session 数据。
2. 先保留原账号数据，告知用户联系维护者进行线下核验。维护者必须使用独立于未验证标识/可能被盗会话的历史身份材料，记录核验人与核验依据；家庭成员资料和能接收新邮箱邮件本身不足以证明原账号归属。
3. **产品待决定**：维护者联系渠道、可接受的独立证据、争议处理与核验后的受控迁移程序。此 PR 不新增管理员默认重置、未认证后门或以家庭成员担保自动接管的接口。未建立可信流程前继续拒绝，不能为兼容恢复旧漏洞。
4. 已设密码但忘记密码且未预先保存恢复码的账号同样不能自助找回。请在仍知道密码时先升级客户端并生成恢复码。
5. 历史漏洞可能已把攻击者密码写到旧账号。现有数据不能区分真实所有者和历史接管者，新增恢复码无法追溯修复此类身份问题；需要单独审计与线下处理，不能把“已设置密码”误称为已验证手机所有者。

## 客户端和上线注意

- 新增登录页“忘记密码 / 旧账号迁移”、设置页“恢复码与会话撤销”，没有恢复码时明确解释迁移路径。
- 当前离线退出只清本地，不能声称服务端已撤销；全部退出网络失败保留本地登录态并提示重试。改密/找回成功清内存 token、持久化 token、bootstrap 与回忆内容缓存。
- 服务端 `UNAUTHORIZED` 的 `details.session_invalid=true` 表示 Bearer 失效，客户端对任意 API 请求统一清理并返回登录页。原密码错误不携带该标记，不会把有效会话清掉。迟到的旧 token 失败响应不会清掉新的 token；中断登录后迟到的签发 token 尽力撤销。
- 改密和找回响应丢失时可能已成功提交；不要声称失败意味着密码未改变。用户可尝试新密码登录；恢复码重放会安全拒绝。生成恢复码响应丢失时请重新验证密码生成，旧码随之失效。
- 旧客户端仍可对新号码注册、有密码账号登录和退出当前会话；无法展示找回/全部撤销入口。旧客户端改密后现有 token 失效，下一次受保护请求 401，建议升级以获得统一登录态清理。
- dev shim 默认关闭。仅本地调试显式 `AUTH_DEV_SHIM_ENABLED=true` 可启用，生产保持 `false`。新增敏感操作即使开启 shim 也要求有效 Bearer。测试夹具显式开启 shim 供现有插件测试使用，安全回归使用 Bearer。
- 先执行新增 Alembic migration，再启动新后端，否则新增字段查询会失败；迁移可以向下删除新增字段（删除恢复码不可逆，降级必须重新生成），不能回滚到有接管漏洞的旧认证逻辑。
- 本次仅在隔离本地 PostgreSQL、临时存储与 mock Flutter 环境验证；不部署、不上传、不合并、不设置真实用户密码、不撤销真实用户会话。App 地址来自已存在本地配置，保留严格 CA 校验。
