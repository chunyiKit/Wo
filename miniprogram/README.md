# Wo 配套微信小程序

与 Wo Android App **账号互通、数据互通**的微信小程序。后端是同一个 FastAPI 服务
（`/api/v1`），小程序只是另一个带 Bearer token 的客户端 —— 数据天然是同一份。

## 图片为什么必须走直链

后端所有媒体端点（回忆 `/raw`、头像 `/avatar`）都要求 `Authorization` 头，
而小程序的 `<image>` 组件**发不出自定义请求头** —— 直接把 `/raw` 塞给它只会
得到一片空白，不报错、也不好排查。

所以后端加了三个「换预签名直链」的端点（C1–C3），返回 COS 的临时签名 URL：
一个自带凭据、无需任何请求头的普通 https 链接。前端这一层由
`utils/media-url.js` 负责：批量换取、按过期时间缓存、失败安静降级。

首页卡片封面走的也是这条链路 —— 唯一的区别是它没有 media id，所以先从
`preview.image_urls`（后端给的 `/raw` 地址）里把 id 解析出来。

| 端点 | 用途 |
|---|---|
| `POST /families/{fid}/plugins/memory/media/urls` | 批量换回忆媒体直链（一页 120 张图只发 1 个请求） |
| `GET /families/{fid}/members/{uid}/avatar-url` | 成员头像直链 |
| `GET /me/avatar-url` | 自己的头像直链 |

### ⚠️ COS 域名也要进白名单

直链指向的是 **COS 域名，不是后端域名**：

```
https://wo-app-1258101097.cos.ap-shanghai.myqcloud.com
```

必须在微信公众平台 → 开发设置里把它加进 **downloadFile 合法域名**。
只加后端域名的话，接口能通、图片仍然全部空白 —— 这是最容易漏的一项。

**同一个域名还要再加进 `uploadFile 合法域名`**（COS 直传用）：上传和下载是两张
白名单，加了一个不等于加了另一个。✅ 两项都已加好。

漏配 uploadFile 的**表现很有欺骗性**：不会报错，直传失败后自动回退到后端中转，
能传上但慢，看起来「功能正常」。所以别用「能不能传」判断它生效了 —— 判断方法
是看上传时有没有一条发往 `cos.ap-shanghai.myqcloud.com` 的 `uploadFile` 请求
（开发者工具 Network 面板 / 真机 vConsole 里都能看到）。

## 写为什么零后端改动

**读**被 `<image>` 卡住过一次，**写**没有：`wx.uploadFile` **支持自定义请求头**，
Bearer 照带、multipart 照传，后端 `POST .../memories/{id}/media` 一个字都不用改。
所以 P3 的后端改动量是 **0**，回忆插件那 10 条路由本来就够用。

代价只是上传要经自己的 CVM 中转（100MB 视频会占后端带宽）—— 这一点后来由
**COS 直传**解决了：现在默认走直传，中转只是兜底（见下）。

### 直传怎么走、什么时候回退

```
① POST .../media/presign   → 服务端签一张票据（POST Object policy，30 分钟）
② wx.uploadFile 到 COS     → 票据字段在前、文件在最后
③ POST .../media/commit    → 服务端核对对象后落库
```

票据里钉死了四件事：只能写这个 `key`、只能是这个 `Content-Type`、ACL 必须是
`private`、大小不得超过上限（照片 20MB / 视频 100MB）。所以**票据可以放心交给
客户端** —— 它拿去也干不了别的。

任一步失败都不打断保存，直接回退到 `POST .../media`（后端中转）。会触发回退的
情况：部署不支持直传（本地磁盘存储返回 501）、票据过期、COS 域名没进
uploadFile 白名单、弱网中断。**回退是无感的，代价只是慢**。

直传有个取舍要说清楚：服务端看不到字节，所以没法像中转那样用 Pillow 完整解码
校验。落库前改做三重检查 —— key 是否属于这个 media_id、大小是否超限、前 16 个
字节的魔数是否与声明的类型矛盾。

### 保存失败可以放心重试

新建回忆、上传媒体都带一个本地生成的 `client_id`（`utils/uuid.js`），服务端把它
**直接当资源 id**：同一个 `client_id` 重复提交，返回的是第一次创建的那个，而不是
再造一份。所以

- 上传中断、某个文件失败 → **页面不退出**，只把失败的文件留在九宫格里，
  原地再点「保存」即可接着传（成功的不会重复）；
- 唯一的注意点：`client_id` 一旦生成就跟着这次编辑走，**别在重试时重新生成**
  （否则幂等失效，会多出一条回忆）。页面里它被存在 `pending[].key` 与
  `this.createKey`，只在首次进入新建页时生成一次。

## 接入一个新插件要做的全部事情

1. 建 `package-<id>/` 分包目录并写页面
2. `app.json` 的 `subpackages` 加一条
3. `utils/plugin-registry.js` 的 `REGISTRY` 加一行

主包不动。后端也**不需要改**（映射放小程序侧，避免为每个插件改 `PluginManifest`）。

### ⚠️ 绑不上？先查这个

`/auth/wechat/bind` 走的是 `login_or_register`：**未知手机号会自动注册新账号**。
所以手机号打错一位不会报错，而是给你建一个空账号 —— 表现为「登录/注册成功但家庭
是空的、卡片墙一片空白」。发现卡片墙空了，先确认手机号是不是输错了。

两页都做了同样的缓冲：真的走了注册分支时会弹提示（登录页说「已为你创建一个」，
注册页说「账号已创建」），不会出现"静悄悄换了个新身份"。

反过来，**在 App 里用验证码登录过、从没设过密码的账号，在这里绑不上**，会报
「手机号或密码错误」（因为服务端没有密码可校验）。要测这类账号，先在 App 里
设一个密码。

## 账号注销

合规依据 —— 微信《小程序平台常见拒绝情形》**3.4.1**：

> 在收集和使用用户任何数据时……**在用户注销账号后应相应删除相关数据**。

配套《个人信息保护法》：第 47 条（个人撤回同意的，应当删除）+ 第 4 条（经
**匿名化**、无法识别且不能复原的，不再属于个人信息，可以保留）。

### 删到什么程度

采用最彻底的一档：

| 数据 | 处置 |
|---|---|
| 手机号、密码、微信 openid/unionid、恢复码、头像 | 清空（手机号与微信标识随之释放，可被重新注册） |
| 自己创建的回忆、留言 | **删除**，连媒体行一起 |
| 自己上传的照片/视频（含挂在别人回忆里的） | 删除 + COS 对象移除 |
| 会话、推送设备、通知、发出的邀请 | 删除 |
| 家庭关系 | 退出全部家庭 |

### 两个设计决定，说一下理由

**1. users 行保留，但清空到匿名。**
记账、宠物、回忆等历史记录的 `created_by` 外键指着这一行，硬删会让它们变孤儿
（或触发意料之外的级联）。清空所有可识别字段后这行**不含个人信息** —— 即 PIPL
第 4 条的匿名化。同时打上 `deleted_at` 时间戳，便于审计与二次清理。

**2. 数据擦除做成插件钩子，不写死在服务里。**
17 个插件里谁持有用户数据，谁负责擦除 —— 核心服务不可能知道每张表的形状。
钩子签在 `registry.register(erase_user=...)` 上，目前只有 memory 实现了
（其它插件不持有个人数据）。将来新插件只要接上钩子就自动合规。

### 主理人注销怎么办

现有 `leave_family` 禁止主理人直接离开，注销也不能绕过这个问题 —— 否则一注销，
全家数据就没了主人。所以：

- 家里还有别人 → **自动移交**给资历最老的成员（admin 优先）
- 家里只剩他一个 → **解散**这个家庭

### 三道闸

密码（后端强制，挡住拿到已登录手机的人）→ 勾选「已知悉」→ 最后一道弹窗。
不可逆操作值得多一次停顿。

## 提审与发布

备案通过后才能提交代码审核。顺序是固定的：

```
① 小程序备案（工信部）  ← 7–20 个工作日，这一步最慢，先做
        ↓
② MP 后台配置《用户隐私保护指引》（勾选相册/摄像头）
        ↓
③ 开发者工具：上传（右上角「上传」→ 填版本号与备注）
        ↓
④ MP 后台 → 管理 → 版本管理 → 把刚传的版本设为「体验版」，自己先扫一遍
        ↓
⑤ 提交审核：填测试账号、勾选已采集隐私、选择服务类目
        ↓
⑥ 审核通过 → 点「发布」→ 线上生效
```

### 三个最容易在这一步翻车的点

**1. 隐私指引没勾「相册 / 摄像头」→ 选照片直接失败。**
`wx.chooseMedia` 是隐私接口。指引里没声明对应信息类型，调用会报
`errno 112: api scope is not declared in the privacy agreement`。
用户同意之前，微信会自己弹官方授权弹窗 —— 这个不用我们实现；
`utils/privacy.js` 只做了两件补充：指引入口（`wx.openPrivacyContract`）+ 选照片前
的一句预告，避免用户被系统弹窗冷不丁打断。

**2. 审核员进不去 → 直接拒。**
小程序一打开是登录页，没有测试账号审核员什么都看不到，这是最常见的驳回原因。
建议**专门注册一个测试账号**（新手机号即可），里面放 2–3 条带照片的回忆，
既让审核员能走通全流程，也避免把真实家庭照片给陌生人看。

**3. 服务类目要和功能对得上。**
个人主体可选类目有限，这个小程序属于**生活记录 / 工具类**。别为了「更好看」
选到需要资质的类目上（医疗、金融、新闻、直播等都要前置审批，个人主体拿不到）。

### 提审前最后过一遍

- [ ] 体验版真机扫一遍：登录 → 首页卡片有图 → 时间线 → 详情 → 发一条带照片的回忆
- [ ] 开发者工具「代码质量」扫描一遍，清掉告警
- [ ] 确认 `setting.urlCheck` 是 `true`（别把调试值传上去）
- [ ] 确认小程序里没有遗留的测试文案、`console.log` 打到线上的敏感信息

```
wx.login() → code
  │
  ├─ POST /auth/wechat/login ── 已绑定 → token → 直接进主页（零输入）
  │
  └─ 未绑定
       ├─ 老用户：登录页(bind) 手机号 + 密码 ─┐
       └─ 新用户：注册页(register) 多填一次确认密码 ─┘
             └─ 重新 wx.login() 取新 code
                   └─ POST /auth/wechat/bind → 登录(或注册) + 绑定 → token
```

两个页面底部的小字互相跳转。**注意后端只有一个绑定接口**（`login_or_register`，
手机号没人用过就顺手建号），所以两页最终调的是同一个 `/auth/wechat/bind` ——
客户端据此给出三种诚实的结果：

| 场景 | 表现 |
|---|---|
| 注册页，号码没人用过 | 「账号已创建」→ 进首页 |
| 注册页，号码已注册且密码正确 | 「已经注册过了，已为你登录」→ 进首页（不折腾用户重填） |
| 登录页，号码还没注册过 | 「这个手机号还没有账号，已为你创建一个」→ 进首页 |

后两种情况之所以要明说：默默换个身份是最糟的失败模式 —— 用户以为登进了那个有
数据的老账号，其实是全新的空壳。

## 约定

- 列表刷新要**就地替换**数据，不要把整页换成 loading（沿用 AGENTS.md 的约束）。
- 展示成员处必须显示真实头像；拿不到直链才回退 emoji。
- 口径对齐 App：心情 / 可见范围 / 字数上限 / 媒体数量上限都来自
  `lib/features/plugins/memory/memory_edit_page.dart`，改一边要改另一边。
- 写操作一律「发完重拉」而不是本地乐观更新：作者头像、计数、private 过滤都在
  服务端拼，本地拼出来的迟早和真实响应不一致。
- 所有可能重试的写请求都带 `client_id`，且不跨重试重新生成。
